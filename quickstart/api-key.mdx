API keys are the primary credential your service uses to authenticate with Atlasent. You create them in the Atlasent Console at [app.atlasent.io](https://app.atlasent.io), assign one or more scopes at creation time, and receive the plaintext value exactly once — Atlasent stores only a SHA-256 hash server-side and can never show you the raw key again.

## Create the key

<Steps>
  <Step title="Log in to the Console">
    Open [app.atlasent.io](https://app.atlasent.io) and sign in to your organization.
  </Step>
  <Step title="Open Settings → API Keys">
    In the left-hand navigation, click **Settings**, then **API Keys**. Click **Generate New Key**.
  </Step>
  <Step title="Choose a name and scope">
    Give the key a descriptive name (for example, `ci-deploy-bot-prod`). For this quickstart, select the **`evaluate`** and **`verify`** scopes. You can create additional keys with narrower scopes — such as `audit`-only for your SIEM integration — later.
  </Step>
  <Step title="Copy the plaintext key immediately">
    The key is shown **once**. Copy it now and store it in your password manager or secrets store. If you lose it, you must rotate and replace it.
  </Step>
</Steps>

## Key prefixes

Keys follow a naming convention that signals their environment:

| Prefix | Environment |
|---|---|
| `ak_live_…` | Production — calls count against your live quota and appear in the production audit chain. |
| `ak_test_…` | Non-production — safe to use in CI, staging, and local development without affecting production records. |

## Store the key as an environment variable

Set the key in your shell or your platform's secret manager before running any SDK or `curl` examples:

```bash
export ATLASENT_API_KEY="ak_live_..."
```

<Warning>
  Never check API keys into source control. Use your platform's secret manager — GitHub Actions secrets, AWS Secrets Manager, HashiCorp Vault, Vercel environment variables, and so on. Atlasent monitors public GitHub repositories and alerts you if a live key appears in a commit.
</Warning>

<Tip>
  Set `ATLASENT_API_KEY` in your CI environment once, at the org or repository level, and all jobs will pick it up automatically. Both the TypeScript and Python SDKs read this variable by default — you do not need to pass it explicitly to the client constructor.
</Tip>

## Key scopes

Assign only the scopes a given key actually needs. A key used solely by your audit pipeline does not need the `evaluate` or `resolve` scopes.

| Scope | What it allows |
|---|---|
| `evaluate` | Call `POST /v1/evaluate` to request an authorization decision and receive a permit token. |
| `verify` | Call `POST /v1/verify-permit` to confirm a permit is still valid before execution. |
| `audit` | Call audit export and list endpoints to download signed audit bundles. |
| `resolve` | Approve or reject escalations routed to a human reviewer. |
