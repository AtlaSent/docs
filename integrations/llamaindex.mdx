The Atlasent LlamaIndex integration wraps tool calls and query engine requests so every action passes through `/v1/evaluate` before it executes. Use `AtlasentAgentStep` to gate tool calls inside a `ReActAgent`, or use `AtlasentQueryPostProcessor` to authorize the query itself before the inner engine runs. Both Python and TypeScript are supported, and every evaluation is recorded in the Atlasent audit chain.

## Install

<CodeGroup>

```bash Python
pip install atlasent-llamaindex
```

```bash TypeScript
npm install @atlasent/llamaindex @atlasent/sdk
```

</CodeGroup>

## Python

### Agent step

`AtlasentAgentStep` injects an authorization check into the `ReActAgent` execution loop. Add it via `extra_steps` and every tool call will be evaluated before LlamaIndex runs it. A denied call raises `DeniedError` before the tool executes.

```python
from atlasent_llamaindex import AtlasentAgentStep

protected_step = AtlasentAgentStep(
    api_key=os.environ["ATLASENT_API_KEY"],
    actor_id="agent_123",
    action_type="model.agent.execute_tool",
)

agent = ReActAgent.from_tools(
    tools=tools,
    step_executor=protected_step,
)
```

### Query post-processor

Use `AtlasentQueryPostProcessor` when the query itself is the action you want to authorize, rather than individual tool calls. It runs before the inner query engine and blocks the query if authorization is denied.

```python
from atlasent_llamaindex import AtlasentQueryPostProcessor

query_engine = index.as_query_engine(
    node_postprocessors=[AtlasentQueryPostProcessor(
        api_key=os.environ["ATLASENT_API_KEY"],
        actor_id="agent_123",
    )]
)
```

On deny, the processor returns a structured denial response — the LLM can observe the reason and adjust — rather than raising an unhandled exception.

### Error handling

Catch `DeniedError` to handle blocked actions without crashing the outer application:

```python
from atlasent.exceptions import DeniedError

try:
    response = agent.chat("Summarize patient 42's recent labs.")
except DeniedError as e:
    print(f"Agent action blocked: {e}")
    # Surface to user or log for audit
```

Both `AtlasentAgentStep` and `AtlasentQueryPostProcessor` support async:

```python
response = await agent.achat("Summarize the patient records.")
```

The async Atlasent client is used automatically in async contexts.

## TypeScript

### `withLlamaIndexGuard`

`withLlamaIndexGuard` wraps an array of tool definitions with authorize-first semantics: `evaluate → verifyPermit → execute`. Only the real tool runs if both checks pass. The wrapper is duck-typed to match LlamaIndex's `BaseTool` and `FunctionTool` shapes with no `llamaindex` dependency in the wrapper itself.

```typescript
import { withLlamaIndexGuard } from '@atlasent/llamaindex';

const guardedTool = withLlamaIndexGuard(deployTool, {
  actionType: 'model.agent.execute_tool',
  actorId: 'agent_123',
  client,
});
```

For multiple tools, pass an array and convert each result to a `FunctionTool`:

```typescript
import { AtlaSentClient } from "@atlasent/sdk";
import { FunctionTool } from "llamaindex";
import { withLlamaIndexGuard } from "@atlasent/llamaindex";

const client = new AtlaSentClient({ apiKey: process.env.ATLASENT_API_KEY! });

const guarded = withLlamaIndexGuard(
  [
    {
      metadata: {
        name: "vector_search",
        description: "Semantic search over the knowledge base",
        parameters: {
          type: "object",
          properties: { query: { type: "string" } },
          required: ["query"],
        },
      },
      execute: async ({ query }) => vectorStore.search(query),
    },
    {
      metadata: {
        name: "upsert_document",
        description: "Add or update a document in the knowledge base",
        parameters: {
          type: "object",
          properties: { id: { type: "string" }, text: { type: "string" } },
          required: ["id", "text"],
        },
      },
      execute: async ({ id, text }) => vectorStore.upsert(id, text),
    },
  ],
  client,
  { agent: "service:knowledge-bot" },
);

const tools = guarded.map((t) => FunctionTool.from(t.execute, t.metadata));
```

By default, a denied call throws `AtlaSentDeniedError`. Set `onDeny: "tool-result"` to return a structured denial object instead:

```typescript
const guarded = withLlamaIndexGuard(tools, client, {
  agent: "service:knowledge-bot",
  onDeny: "tool-result",
});

// execute() returns on deny:
// { denied: true, decision: "deny", evaluationId: "...", reason: "..." }
```

### Dynamic actor and context

Pass a resolver function instead of a static string to set the actor ID or extra context dynamically per call:

```typescript
withLlamaIndexGuard(tools, client, {
  agent: (toolName, input) => `user:${input.userId}`,
  extraContext: (toolName, input) => ({ environment: "production", tool: toolName }),
});
```

### Result annotation

Object results from guarded tools are automatically annotated with permit metadata:

```json
{
  "results": [],
  "_atlasent_permit_id": "permit_abc123",
  "_atlasent_audit_hash": "sha256:..."
}
```

Non-object results pass through unchanged.

<Tip>
  Use stable action types — such as `data.query` or `ehr.write` — rather than tool function names when defining your policy mappings. Tool names change during refactors; action types are the identifiers your audit chain and compliance reviews depend on.
</Tip>
