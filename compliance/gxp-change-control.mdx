AtlaSent's `gxp:change-control` action class enforces change-control authorization gates for regulated systems, covering software validation lifecycle changes, infrastructure modifications, and manufacturing process updates.

## Requirement-to-primitive mapping

| Ref | Requirement | AtlaSent primitive |
|---|---|---|
| ICH Q10 §3.2          | Change management must assess impact and obtain approvals | `qrb_status`, `approvals[]` required context; QRB approval gate. |
| EU GMP Annex 15 §10   | Validation change control must document impact on validated state | `validation_impact`, `gamp_category` gates. |
| EU GMP Annex 11 §10   | Changes to computerized systems must follow formal change control | `system_name`, `cfr_part_11_applicable` gates. |
| 21 CFR 211.100        | Written procedures required for production and process controls | `change_type`, `risk_level` authorization. |
| GAMP 5 Chapter 8      | Risk-based approach to software change validation | `gamp_category`, `risk_level` routing. |
| 21 CFR Part 11        | Electronic record integrity for audit-controlled changes | `cfr_part_11_applicable` gate + audit chain. |

## Implementation checklist

- [ ] Register the change in your CMS before calling AtlaSent.
- [ ] Include your CMS change identifier in the evaluation context (for example `change_ticket_id`) so the audit entry links back to the change record.
- [ ] Populate `gamp_category` per GAMP 5 (1–5).
- [ ] Set `risk_level` to `minor`, `major`, or `critical` per SOP.
- [ ] Obtain QRB sign-off; set `qrb_status: "approved"` before release.
- [ ] Set `validation_impact` to `none`, `revalidation_required`, or `full_validation`.
- [ ] Set `rollback_plan_verified: true` before production changes.
- [ ] Store the permit ID on the change record.
- [ ] Call `/v1/permits/{id}/verify` after apply/rollback to close the loop.
