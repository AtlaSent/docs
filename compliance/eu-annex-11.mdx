EU GMP Annex 11 is the EMA guideline governing **computerized systems** in regulated GMP environments, including pharmaceutical manufacturing, batch release, and clinical data management. When AI agents process GMP data, batch records, or regulated manufacturing records, Annex 11 applies. Atlasent satisfies Annex 11's core requirements through an append-only, hash-linked audit chain, policy-based access controls, and tamper-evident permit tokens that serve as the electronic authorization record for each regulated action.

## Framework mapping

The table below maps each relevant Annex 11 clause to the specific Atlasent primitive that satisfies it.

| Annex 11 clause | Requirement | Atlasent primitive |
|---|---|---|
| Clause 4.3 | Supplier and service provider assessment | VQP package, vendor qualification |
| Clause 4.7 | Record of all events affecting a system | Append-only audit chain, policy version tracking |
| Clause 7.1 | Data integrity — protected from modification | Hash-linked entries, fail-closed on error |
| Clause 9 | Electronic signatures | Permit tokens, actor attribution in audit |
| Clause 12.1 | Audit trail — all GxP data modifications | Evaluation audit chain, all decisions recorded |
| Clause 12.4 | Review of audit trails | Audit export API, Console audit viewer |
| Clause 14 | Disaster recovery | RPO 5 minutes, RTO 1 hour |

<Note>
  Clause 4.3 requires a formal supplier assessment before placing Atlasent into a validated GMP system. Request the **Vendor Qualification Package (VQP)** from [compliance@atlasent.io](mailto:compliance@atlasent.io) — it provides the structured mapping your Quality team needs to complete supplier qualification.
</Note>

## Starter policy rules

The following policy rules implement the core Annex 11 data-integrity and access-control requirements. Deny rules for data deletion and audit modification are mandatory for GMP use.

```json
[
  { "action_type": "batch.read",    "decision": "allow" },
  { "action_type": "batch.write",   "decision": "allow" },
  { "action_type": "batch.release", "decision": "require_approval" },
  {
    "action_type": "batch.delete",
    "decision": "deny",
    "deny_code": "DENY_POLICY",
    "message": "EU Annex 11 Clause 7.1: GMP data must not be deleted"
  },
  {
    "action_type": "audit.modify",
    "decision": "deny",
    "deny_code": "DENY_POLICY",
    "message": "EU Annex 11 Clause 12.1: Audit trails must not be modified"
  },
  {
    "action_type": "access.bypass",
    "decision": "deny",
    "deny_code": "DENY_POLICY",
    "message": "EU Annex 11 Clause 4.3: Access controls must not be circumvented"
  }
]
```

<Warning>
  `batch.release` uses `require_approval` rather than a direct `allow`. This routes the action through the Atlasent operator approval queue before a permit is issued. You must configure an approval workflow in the Console before deploying agents that perform batch release operations.
</Warning>

## Implementation checklist

Complete the following steps before deploying agents into a validated GMP environment.

<Steps>
  <Step title="Request the VQP">
    Email [compliance@atlasent.io](mailto:compliance@atlasent.io) to receive the Vendor Qualification Package. Include the package in your Computerized Systems Validation (CSV) documentation to satisfy Clause 4.3.
  </Step>
  <Step title="Import the EU Annex 11 preset">
    Import the `eu_annex_11` framework preset in the Console under **Policies → Presets**. Review each rule and adapt action type names to match your system's vocabulary.
  </Step>
  <Step title="Assign unique actor IDs">
    Assign a unique, human-readable `actor_id` to each AI system component. This ID appears in every audit entry and enables Clause 12.4 audit trail reviews.
  </Step>
  <Step title="Store permit IDs with records">
    Store the `permit_id` returned by each `allow` decision alongside the batch record modification in your system. This provides the authorization evidence required by Clause 9.
  </Step>
  <Step title="Route deny events to your QMS">
    Configure the Atlasent webhook to push `deny` decisions into your QMS deviation workflow. Each deny event is a Clause 12.1 audit finding that may require investigation.
  </Step>
  <Step title="Archive signed audit bundles">
    Export and archive signed audit bundles for the required GMP retention period — typically 5 to 15 years depending on the product lifecycle stage.
  </Step>
</Steps>
