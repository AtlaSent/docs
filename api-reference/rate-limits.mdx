## Response headers

`/v1/evaluate` responses carry these headers:

| Header | Meaning |
|---|---|
| `X-RateLimit-Limit`     | Requests allowed per minute. |
| `X-RateLimit-Remaining` | Requests left in the current window. |
| `X-RateLimit-Reset`     | Unix seconds when the window resets. |

## 429 response body

A 429 uses the standard error envelope. On `/v1/evaluate` and
`/v1-verify-permit` it carries `retry_after_ms`:

```json
{
  "error": "unavailable",
  "message": "Runtime cannot decide right now; retry shortly",
  "status": 429,
  "retry_after_ms": 60000
}
```

Other endpoints return `"error": "rate_limited"`. When `retry_after_ms` is
present, use it for back-off; otherwise back off exponentially.

## Handling 429 responses

Respect the server's retry hint, then back off exponentially. The SDKs do this for you; if you're calling the API directly:

```python
import time
from atlasent import AtlaSentClient, RateLimitError

client = AtlaSentClient(...)

def evaluate_with_backoff(req, max_retries=4):
    for attempt in range(max_retries):
        try:
            return client.evaluate(**req)
        except RateLimitError as e:
            if attempt == max_retries - 1:
                raise
            wait_s = e.retry_after if e.retry_after else (2 ** attempt)
            time.sleep(wait_s)
```

<Warning>
  Do not retry 429s indefinitely. For a regulated agent, a sustained 429 should be treated as **deny** — the agent halts and surfaces a clear error to the user.
</Warning>
