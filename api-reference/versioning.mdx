The current Atlasent API version is **v1**, and it is the only version. All endpoints are served at `https://api.atlasent.io/v1/*`. New capabilities ship as additive evolution on `v1` — they do not introduce a new URL namespace, and you never need to update a URL to receive bug fixes or new optional features.

## Current version

| Property | Value |
|---|---|
| Stable version | `v1` |
| Base URL | `https://api.atlasent.io/v1/` |
| Status | Generally Available |

## URL path versioning

Atlasent uses URL path versioning. The version segment `/v1/` is part of every endpoint path and stays `/v1/` indefinitely. New endpoints land under `/v1/*`; they never introduce `/v2/*` or `/v3/*` URL namespaces. When you see an endpoint in this reference, the URL you deploy against today is the URL you will use in two years.

## Stability tiers

Different endpoint groups carry different stability commitments. The tier determines how much notice you receive before a breaking change or removal.

| Tier | Stability | Examples |
|---|---|---|
| GA | Stable; breaking changes require 90-day notice | `/v1/evaluate`, `/v1/verify-permit`, `/v1/audit/exports` |
| Beta | Stable but may have minor changes; 3-month notice | Evidence exports, Go SDK, LangChain/LlamaIndex integration |
| Preview | Subject to change without notice | SCIM 2.0, SIEM export, batch/streaming evaluate, GraphQL |

Build critical production workflows on GA endpoints. Use Beta endpoints with the understanding that a 3-month migration window accompanies any breaking change. Avoid automating Preview endpoints in production without first consulting your account team.

## Backward-compatible changes

The following changes are additive and do not require a version bump or deprecation notice. Write your client to tolerate them.

- Adding new **optional** request fields (your client ignores fields it does not send)
- Adding new **response fields** (configure your deserializer to ignore unknown fields)
- Adding new endpoint paths under `/v1/*`
- Adding new enum values to extensible fields (use a default or fallback case for unknown values)
- Refining human-readable `message` text in error responses (the `error` code and HTTP status are stable)

<Warning>
  If your client deserializes API responses with strict schema validation that rejects unknown fields, new response fields will cause failures. Configure your deserializer to ignore unknown fields so additive changes do not break your integration.
</Warning>

## Breaking changes

The following changes are breaking. Atlasent will not make them inside `v1` without going through the full deprecation cycle:

- Removing an endpoint
- Renaming a required request field
- Changing the type of a request or response field
- Removing an enum value from a response field
- Adding a mandatory field to a request body
- Changing authentication requirements for an endpoint

## Deprecation policy

When an endpoint or field must be deprecated, Atlasent follows this process:

<Steps>
  <Step title="Announcement">
    All org admins with active API keys receive an email notification. The deprecated endpoint begins returning a `Deprecation` response header. A changelog entry is published.
  </Step>
  <Step title="Grace period">
    The deprecated endpoint continues to function in full for the entire notice period: 90 days for GA endpoints, 3 months for Beta endpoints.
  </Step>
  <Step title="Removal">
    After the notice period, the endpoint returns `410 Gone` with a JSON body that includes a `migration_guide_url`.
  </Step>
</Steps>

When a GA endpoint is removed, the `410` response body looks like this:

```json
{
  "error": "endpoint_removed",
  "message": "This endpoint was removed on 2026-01-01. See the migration guide.",
  "migration_guide_url": "https://docs.atlasent.io/guides/migration"
}
```

## SDK versioning

SDK major versions follow standard semantic versioning for each language package and are independent of the API version. An `@atlasent/sdk@2.x` release represents a breaking change in SDK ergonomics or the TypeScript type surface — it is not "Atlasent API v2." The API contract remains `/v1/`.

<Note>
  Subscribe to API changelog notifications in **Console → Settings → Notifications** to receive email updates whenever an endpoint is added, deprecated, or removed.
</Note>
