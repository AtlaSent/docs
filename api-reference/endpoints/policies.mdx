---
title: "Policies API: create, list, and manage policy bundles"
sidebarTitle: "Policies"
description: "Create, list, and manage policy bundles that govern authorization decisions. Policies are immutable once published — updates create new versions."
---

Policies are the rule sets that the Atlasent evaluation engine enforces at runtime. Each policy bundle contains an ordered list of rules that the engine evaluates against every incoming authorization request. You create policies in `draft` status, where you can iterate on rules without affecting live traffic. Promoting a policy to `shadow` evaluates it on real traffic but does not enforce the decision — useful for validating rule logic before go-live. Promoting to `enforce` makes the policy fully active and binding on all subsequent evaluations.

## Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/v1/policies` | List policy bundles |
| `POST` | `/v1/policies` | Create a new policy bundle |
| `GET` | `/v1/policies/{id}` | Get a specific bundle by ID |
| `PUT` | `/v1/policies/{id}` | Update rules or lifecycle status |
| `DELETE` | `/v1/policies/{id}` | Delete a `draft` policy bundle |

---

## GET /v1/policies

Returns all policy bundles visible to your organization.

### Query parameters

<ParamField query="status" type="string">
  Filter by lifecycle status — one of `draft`, `shadow`, `enforce`. Omit to return all statuses.
</ParamField>

<ParamField query="action_type" type="string">
  Filter by the action type the policy governs (e.g. `"production.deploy"`).
</ParamField>

<ParamField query="limit" type="integer">
  Maximum results to return. Default `50`, maximum `200`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor from a previous response.
</ParamField>

### Example request

<CodeGroup>
```bash cURL
curl https://api.atlasent.io/v1/policies \
  -H "Authorization: Bearer $ATLASENT_API_KEY"
```
</CodeGroup>

### Example response

```json
{
  "policies": [
    {
      "id": "pol_01j8abc...",
      "org_id": "org_01xyz...",
      "action_type": "production.deploy",
      "version": "3",
      "status": "enforce",
      "rules": [
        {
          "id": "require-reviews",
          "condition": { "context.review_count": { "lt": 2 } },
          "decision": "deny",
          "deny_code": "DENY_POLICY"
        },
        {
          "id": "allow",
          "condition": {},
          "decision": "allow"
        }
      ],
      "created_at": "2026-05-20T09:00:00Z"
    }
  ],
  "next_cursor": null,
  "total": 1
}
```

## POST /v1/policies

Creates a new policy bundle in `draft` status. Promote it to `shadow` to observe its decisions on live traffic without enforcement, or directly to `enforce` to make it binding. Use `PUT /v1/policies/{id}` to update status or rules.

### Request body

<ParamField body="action_type" type="string" required>
  The action type this policy governs. Must match an `action.type` value your system sends to `POST /v1/evaluate`.
</ParamField>

<ParamField body="rules" type="array" required>
  Ordered list of rule objects. Rules are evaluated top-to-bottom; the first matching rule wins.

  <Expandable title="rule fields">
    <ParamField body="rules[].id" type="string" required>
      A stable identifier for this rule within the bundle (e.g. `"require-reviews"`).
    </ParamField>
    <ParamField body="rules[].condition" type="object" required>
      A condition expression evaluated against the incoming request. An empty object `{}` matches unconditionally.
    </ParamField>
    <ParamField body="rules[].decision" type="string" required>
      The decision to emit when this rule matches — one of `allow`, `deny`, `hold`, `escalate`.
    </ParamField>
    <ParamField body="rules[].deny_code" type="string">
      Machine-readable code included in the evaluation response when this rule produces a `deny` decision (e.g. `"DENY_POLICY"`).
    </ParamField>
  </Expandable>
</ParamField>

### Policy object fields

<ResponseField name="id" type="string">
  Stable unique identifier for the policy bundle (prefix `pol_`).
</ResponseField>

<ResponseField name="org_id" type="string">
  Organization that owns this policy.
</ResponseField>

<ResponseField name="action_type" type="string">
  The action type this policy governs.
</ResponseField>

<ResponseField name="version" type="string">
  Monotonically incrementing version number. Each new bundle for the same `action_type` increments this counter.
</ResponseField>

<ResponseField name="status" type="string">
  Lifecycle status — `draft`, `shadow`, or `enforce`. `draft` policies are not evaluated. `shadow` policies are evaluated but decisions are not enforced (logged only). `enforce` policies are fully active and binding.
</ResponseField>

<ResponseField name="rules" type="array">
  The ordered rule list as submitted.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp when the bundle was created.
</ResponseField>

### Example request

<CodeGroup>
```bash cURL
curl -X POST https://api.atlasent.io/v1/policies \
  -H "Authorization: Bearer $ATLASENT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "action_type": "production.deploy",
    "rules": [
      {
        "id": "require-reviews",
        "condition": { "context.review_count": { "lt": 2 } },
        "decision": "deny",
        "deny_code": "DENY_POLICY"
      },
      {
        "id": "allow",
        "condition": {},
        "decision": "allow"
      }
    ]
  }'
```
</CodeGroup>

### Example response

```json
{
  "id": "pol_01j8new...",
  "org_id": "org_01xyz...",
  "action_type": "production.deploy",
  "version": "4",
  "status": "draft",
  "rules": [
    {
      "id": "require-reviews",
      "condition": { "context.review_count": { "lt": 2 } },
      "decision": "deny",
      "deny_code": "DENY_POLICY"
    },
    {
      "id": "allow",
      "condition": {},
      "decision": "allow"
    }
  ],
  "created_at": "2026-05-26T10:00:00Z"
}
```

## GET /v1/policies/{id}

Retrieves a specific policy bundle by its ID.

### Path parameters

<ParamField path="id" type="string" required>
  The policy bundle ID (prefix `pol_`).
</ParamField>

### Example request

<CodeGroup>
```bash cURL
curl https://api.atlasent.io/v1/policies/pol_01j8abc... \
  -H "Authorization: Bearer $ATLASENT_API_KEY"
```
</CodeGroup>

---

<Note>
  Policies support in-place updates via `PUT /v1/policies/{id}` — you can revise rules and promote status without creating a new bundle. The policy audit trail records every status transition and rule change. Use `shadow` mode to validate rule logic on live traffic before promoting to `enforce`.
</Note>

<Warning>
  Promoting a policy to `enforce` takes effect immediately for all subsequent evaluations. Test your rule logic in `shadow` mode on a staging environment before promoting to `enforce` in production.
</Warning>
