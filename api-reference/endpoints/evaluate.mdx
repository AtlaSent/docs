---
title: "POST /v1/evaluate — evaluate an authorization request"
sidebarTitle: "POST /v1/evaluate"
description: "Submit actor, action, and context to the Atlasent policy engine. Returns allow, deny, hold, or escalate with a single-use permit token on allow decisions."
---

Every protected operation in your system must pass through `POST /v1/evaluate` before it executes. You submit the actor making the request, the action they want to perform, an optional target resource, and any runtime context your policies need to make a decision. Atlasent evaluates your organization's active policy bundle in real time and returns one of four canonical decisions — along with a single-use permit token whenever the decision is `allow`.

## Request

**`POST https://api.atlasent.io/v1/evaluate`**

All requests must include an `Authorization: Bearer` header and a `Content-Type: application/json` header.

### Request body

<ParamField body="actor" type="object" required>
  The identity making the request.

  <Expandable title="actor fields">
    <ParamField body="actor.id" type="string" required>
      Unique identifier of the entity requesting the action — a user ID, service account ID, or agent ID.
    </ParamField>
    <ParamField body="actor.role" type="string">
      Role of the actor (e.g. `"engineer"`, `"admin"`). Passed to policy conditions for role-based rules.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="action" type="object" required>
  The action being requested.

  <Expandable title="action fields">
    <ParamField body="action.type" type="string" required>
      Action category string — must match a configured policy action type (e.g. `"production.deploy"`, `"data:export"`).
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="target" type="object">
  The resource being acted upon. Optional, but recommended for environment-scoped policies.

  <Expandable title="target fields">
    <ParamField body="target.id" type="string">
      Identifier of the specific resource (e.g. a service name, dataset ID).
    </ParamField>
    <ParamField body="target.environment" type="string">
      Deployment environment — for example `"production"`, `"staging"`, or `"development"`. Production targets carry a higher baseline risk score.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="context" type="object">
  Arbitrary key-value pairs passed directly to policy rule conditions. Values may be strings, numbers, or booleans. Use this field to supply any runtime signals your policies rely on — commit SHAs, review counts, IP addresses, ticket IDs, and so on.
</ParamField>

### Example request

<CodeGroup>
```bash cURL
curl -X POST https://api.atlasent.io/v1/evaluate \
  -H "Authorization: Bearer $ATLASENT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "actor": { "id": "user_123", "role": "engineer" },
    "action": { "type": "production.deploy" },
    "target": { "id": "my-service", "environment": "production" },
    "context": {
      "git_sha": "abc1234",
      "branch": "main",
      "review_count": 2
    }
  }'
```
</CodeGroup>

## Response

**Status: `200 OK`**

Atlasent always returns `200` for a completed evaluation, regardless of whether the decision is `allow` or `deny`. A non-`200` status means the request itself failed (see [Error codes](#error-codes) below).

<ResponseField name="decision" type="string" required>
  The authorization outcome. One of `allow`, `deny`, `hold`, or `escalate`.
</ResponseField>

<ResponseField name="decision_id" type="string" required>
  Stable identifier for this decision (prefix `dec_`). Reference this in support requests and when creating an escalation.
</ResponseField>

<ResponseField name="permit" type="object">
  Present only when `decision` is `allow`. Contains the single-use permit token your system must consume before executing the protected action.

  <Expandable title="permit fields">
    <ResponseField name="permit.token" type="string">
      The opaque permit token string (prefix `pt_`). Pass this to `POST /v1/verify-permit` immediately before execution.
    </ResponseField>
    <ResponseField name="permit.expires_at" type="string">
      ISO 8601 timestamp. Permits expire 15 minutes after issuance. Attempting to consume an expired permit returns a `permit_expired` error.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="deny_code" type="string">
  Machine-readable denial reason — present only when `decision` is `deny`. For example: `"DENY_POLICY"`, `"DENY_RISK"`.
</ResponseField>

<ResponseField name="risk_score" type="number">
  Composite risk score from `0` (no risk) to `100` (maximum risk). Derived from the weighted risk envelope.
</ResponseField>

<ResponseField name="risk_level" type="string">
  Human-readable risk tier: `low` (0–30), `medium` (31–60), `high` (61–85), `critical` (86–100).
</ResponseField>

<ResponseField name="risk_envelope" type="object">
  Full risk envelope object. Always present on responses from engine version `wire-v1@1.0.0+`. Contains the composite score, per-factor breakdown (when `explain: true` is passed), and details of any automatic hold promotion.

  <Expandable title="risk_envelope fields">
    <ResponseField name="risk_envelope.weighted_score" type="number">
      Composite risk score in [0, 1]. A score ≥ 0.70 triggers an automatic hold promotion — even if the policy engine decision would otherwise be `allow`.
    </ResponseField>
    <ResponseField name="risk_envelope.engine_decision" type="string">
      The policy engine's decision *before* envelope promotion. Same vocabulary as `decision`.
    </ResponseField>
    <ResponseField name="risk_envelope.envelope_decision" type="string">
      The decision resolved by the risk envelope after promotion. Always equals the outer `decision` field.
    </ResponseField>
    <ResponseField name="risk_envelope.promoted" type="boolean">
      `true` when the envelope raised the engine decision's severity. The envelope enforces most-restrictive-wins and cannot soften a `deny`.
    </ResponseField>
    <ResponseField name="risk_envelope.hard_blocks" type="array">
      Deny codes that unconditionally blocked the action regardless of score.
    </ResponseField>
    <ResponseField name="risk_envelope.factors" type="array">
      Per-factor breakdown — only present when `explain: true` was passed on the request. Each item contains `factor`, `value`, `weight`, and `reason`.
    </ResponseField>
  </Expandable>
</ResponseField>

### Decision values

| Value | What it means | What you should do |
|---|---|---|
| `allow` | Action is permitted by policy. | Consume the `permit.token` via `POST /v1/verify-permit`, then execute. |
| `deny` | Action is blocked by policy. | Do not execute. Surface `deny_code` and `message` to the caller. |
| `hold` | Action is paused pending automated or human review. | Wait and poll `GET /v1/permits/{id}` until the hold resolves. |
| `escalate` | Action requires explicit human approval. | Create an escalation via `POST /v1/escalations` and notify the approver. |

### Risk envelope

The `risk_score` is computed from a set of weighted factors. When you include `"explain": true` in the request body, the response includes a `risk_envelope.factors` array with a per-factor breakdown.

| Factor | Description |
|---|---|
| `ACTION_SENSITIVITY` | How sensitive the requested action type is. |
| `ACTOR_AUTHORITY` | Whether the actor holds sufficient authority. |
| `ORG_POLICY_STRICTNESS` | Org-level strictness setting (0 = permissive, 1 = strict). |
| `ENVIRONMENT` | Risk contributed by the target environment (production is higher). |
| `CONTEXT_ANOMALY` | Anomaly score from unusual context values. |
| `HISTORY` | Prior denies or holds on this actor elevate their score. |
| `BEHAVIOR_BASELINE` | Deviation from the actor's historical baseline. |

<Note>
  A composite risk score of 70 or higher triggers an automatic hold promotion — even if the policy engine decision would otherwise be `allow`. The envelope enforces most-restrictive-wins and cannot soften a `deny`.
</Note>

## Error codes

A non-`200` response means Atlasent could not complete the evaluation. Your code should treat any evaluation failure as a **deny** — never execute a protected action when the evaluation endpoint is unreachable or returns an error.

| HTTP status | Error code | Description |
|---|---|---|
| `400` | `bad_request` | Request body is malformed or missing required fields. |
| `401` | `unauthenticated` | No valid credential provided, or the credential is expired. |
| `403` | `forbidden` | Credential is valid but does not have permission to call this endpoint. |
| `404` | `policy_not_found` | No active policy bundle found for the given `action.type`. |
| `422` | `invalid_action_type` | The `action.type` value is malformed or not recognized. |
| `503` | `unavailable` | The evaluation engine is temporarily unavailable. Fail closed — do not proceed. |

<Warning>
  `POST /v1/evaluate` is fail-closed. If you receive a `503` or a network error, treat the outcome as `deny` and do not execute the protected action.
</Warning>
